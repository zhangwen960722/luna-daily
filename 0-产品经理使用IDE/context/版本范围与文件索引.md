> ⑲ **待发送账单编辑三处修正（产品实测反馈）** —— ① **「添加流水」候选改为默认全选**：原先默认不勾选 → 弹窗一打开「确认添加」就是灰的，看着像"没有保存按钮"（实测按钮一直在、勾一条就亮）；现与「生成账单」一致默认全选，只有候选为空才置灰。② **改账单日期的 toast 写出重算结果**：月结类账期「账单月第 N 号不晚于账单日 → 顺延下一月同一号」，会出现"改了账单日、到期日确实没变"的正常结果 —— 原 toast 只说"已重算"就被读成"没重算"；现到期日变了报 `{旧} → {新}`、没变报 `按「月结+15」推导，到期日期仍为 {值}`，handler 同时改为直接取事件值（与 `v-model` 时序解耦）。③ **账单编辑进「操作时间线」**（推翻⑱的"不留痕"）：每次编辑留一条 `编辑账单`，**只记 时间 + 操作人 + 动作类型**（移除流水 / 添加流水 / 修改账单日期）、不记增减了几条流水，一期只留最近一次；**连带修掉**：「生成账单」条目原拿**账单日**当生成时间（而账单日正是待发送阶段可改的）→ 改用真实生成时间戳 `ar_bill.generated_at`（回退账单日），否则改完日期会出现"编辑排在生成之前"的荒谬顺序。
> ⑳ **账期「天数/号」纠正 + 账单编辑加保存 + 草稿池去勾选 + 待发送批量发送（四条产品反馈）** —— ① **「天数/号」不再有「月末」**：产品指出客户管理里这个字段**只能填数字**，此前"0 = 月末"是自造口径（正是"改账单日期后到期日看不出变化"的根因）。现口径 `days_or_date` = **1–31 的整数**（客商中心数据设计 / RDD 同步为「只填数字，无月末 / 月初」），**0 / 空 = 未填 → 不允许出账**（与账期缺失、事件型同一路径），「该月无该号 → 取该月月末」保留；演示数据 华美 · 深圳飞点 `月结+月末 → 月结+30`（08 月两张到期日 08-31 → 08-30、账期天数 31 → 30，两端同步）。② **账单详情加「保存」按钮**：改账单日期改为**草稿式编辑** —— 到期日**实时预览 + `未保存` 黄 tag**，点底部「保存」才落库（重算到期日 / 账期天数、跨月重编账单号、写留痕），无改动置灰，未保存关闭即丢弃。③ **草稿池去掉勾选列**（**19 → 18 列**），生成账单收敛为**单一入口**（一律空态弹窗逐级选条件），要只出其中几条时在弹窗内逐条取消。④ **「待发送」新增「批量发送」**（新增 **R69** + 弹窗 6）：按**客户**一次发一批（多主体 / 多币种），选客户 → 该客户名下待发送账单**默认全选** → 汇总按币种分别列（不跨币种合计）→ 红底提示不可撤回 → 二次确认**列出账单号**、按钮带张数 → 逐张写 `sent_at`。
> ㉑ **负数应收（贷记单）的结清口径定案：新增「结转钱包」（R70）** —— 产品质疑「负数账单怎么做核销？走核销的话客户钱包平白多钱就是 BUG」。定论：① 负数账单**本来就进不了核销**（判据 `未核销金额 > 0` 天然排除）；② 但**负数应收流水是业务事实驱动、系统自动产生的**（识别到赔付即插一条负应收），**不取决于客户是否合作** → "禁止单独成账、留到下期抵扣"不成立（客户一不合作就永久挂账）；③ 也**不能借道「充值 + 提现」**（充值记录是**对客凭证**，客户在货主端看得见，垫一笔假充值直接暴露 + 对账无据）；④ **不造第二套"贷记台账"**（钱包就是"客户可用额度"容器，再造 = 两个池子都要轧账）。**方案**：净额 > 0 → 应收账单（负数流水作账单内「赔付抵扣 −N」行）；**净额 ≤ 0 → 贷记单**（不参与核销 / 不发送客户 / 不进账龄 / 不计入未核销金额）→ 财务「**结转钱包**」→ 写 `flow_type = 70 赔付入账` 流水、钱包 += \|净额\| → **有欠款正常核销、要现金走提现**（无需先充值）；「资金流水」页可「撤销入账」（`flow_type = 80` 反向流水，余额不足阻断）。**不需要客户确认**（否则客户不合作即死锁）；**"已结转"用派生判定、不新增状态枚举；表结构零改动**，只加 2 个 `flow_type` 值。同步：PRD R70 + 待发送行操作 + 生成账单净额分支 + **未核销金额口径加 `> 0`（堵 BUG）** + A31 + §12.4；数据设计新小节 + 枚举 70/80 + 幂等；RDD ⑭ + AC19；原型 4 页（含演示贷记单 `AR-GD-202608-00003` 已结转）。
> ㉒ **贷记单流程补正（产品实测反馈两项）** —— ① **贷记单必须能发送给客户**：上一版为"避免客户不合作时卡死"而禁用发送，产品指出是**流程缺陷**（客户侧看不到单据、没有凭据）。现改为**照常发送 + 走同一套确认 + 满 7 个自然日未确认由系统自动确认兜底**（R16 现成机制），**结转前置 = 客户已确认**（与核销对称）—— 闭环与防死锁兼得；货主端**同步展示贷记单**（列表/详情「贷记单」黄 tag + 悬浮说明，已核销/未核销金额显示 `—`），员工端「已发送」Tab 同样以 tag 替换「未核销」。② **撤销入账必须做余额校验但不能只报"余额不足"**：存在"入账 300 → 这笔钱已被拿去核销另一张账单"的情形 —— 现改为**列出占用去向**（核销到哪张账单 / 提现）并指引「**先反核销后再撤销**」，且**撤销只能是全额**（不允许部分撤销）。③ 连带：「结转钱包」入口从「待发送」移到**「已发送」**（要先发送、确认后才结转）；**结转进「操作时间线」**；演示贷记单改挂 **华美 · 广东飞点 · CNY**（客户端才可见），钱包 800.00 → 1,100.00，时间线 生成 → 发送 → 自动确认 → 结转钱包，两端资金账户/资金流水同步；财务 PRD **v1.7 → v1.8**、数据设计 **v0.10 → v0.11**、RDD **v1.7 → v1.8**。

> ㉓ **贷记单的「待发送」阶段口径 + 作废闸门（产品追问「待发送能改吗 / 发送后能作废吗」）** —— 结论：**保留三段式（待发送 → 发送 → 客户确认 → 结转），不做"生成即已发送 / 已确认"** —— 贷记单是**我司对客的付款承诺**，对外文件必须有人复核后发出（赔付流水虽已审计，但挂错组合 / 金额错只有财务看得出来），而「待发送」正是**唯一"改完不用惊动客户"的纠错窗口**；"客户不合作会卡死"已由 7 天自动确认（R16）兜底，不需要靠"生成即确认"解决。补三处：① **待发送照旧可改可废**（加 / 删流水、改账单日期 → 保存；整张可作废、流水释放回草稿池下期重出），并在**待发送列表的账单金额右侧加「贷记单」黄 tag**（否则负债单混在催款单里没人注意）；② **新增作废闸门** —— 原先作废只判「核销状态 = 未核销」，而**贷记单的核销状态恒为未核销** → 客户已确认的贷记单也挂着「作废」按钮，客户认账后财务一键删凭据、两边对不上账。现改为 **贷记单「客户已确认」（含系统自动确认）后作废入口置灰 + 悬浮说明原因**（要冲正走「运单侧新增反向流水 → 下期抵扣」，已结转的指引去「资金流水」撤销该笔「赔付入账」），**未发送 / 已发送未确认仍可作废**；③ **贷记单照常参与「批量发送」**（原「只发正数账单」口径作废），弹窗内**金额列带「贷记单」tag**、小结条把**应收合计与贷记单合计分开列**（应收是我司要收的钱、贷记单是我司要付的钱，代数相加财务看不懂）。演示数据新增一张**待发送贷记单 `AR-GD-202609-00001`**（华美 · 广东飞点 · CNY −450.00，2 条赔付流水）→ 待发送 3 → **4 张**，正好演示"待发送可改可废、发送后置灰"。同步 PRD（R63 / R69 / R70 / A31 / §5.2 列表与弹窗 6）、数据设计（作废前置判据）。
