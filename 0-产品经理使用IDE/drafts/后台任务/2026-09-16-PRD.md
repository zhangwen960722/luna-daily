## 1. 需求定义

### 1.1 背景与现状

各子应用模块（商品管理、地址管理、港口管理等）均涉及 Excel 导入功能，但导入任务分散在各模块内，缺乏统一入口查看导入结果。当导入出现部分失败时，用户需要到各自模块查找失败原因，无法集中下载错误数据。

### 1.2 目标与成功口径

- **目标**：搭建统一的**任务**监控模块（导入 + 导出），员工端和货主端均可查看各模块任务结果 —— 导入任务下载错误数据，**导出任务下载结果文件**
- **成功口径**：导入任务统一可见、错误数据可一键下载；**导出任务提交后进度可见、结果文件可一键下载**（导出任务的**来源与范围**见 §5.2 / R07）

### 1.3 范围与边界

**In Scope（本期 P0）**：
- 后台任务列表（任务编号/模块名称/任务类型/状态/结果/创建人/时间）
- 搜索（任务编号/模块名称/任务状态）
- 下载错误数据（导入任务、fail_count > 0 时）
- **导出任务监控与结果下载**（2026-09-16 新增：财务「账单管理 → 已发送 → 导出」提交的任务落本模块，完成后可下载结果文件）

**Out of Scope**：
- ~~导出任务监控~~ —— **已纳入本期**（原「后续用 BI 工具做导出、无需监控」的口径作废）
- 任务重试/取消
- 任务详情页

### 1.4 影响范围

- **影响角色**：员工/运营、货主
- **依赖系统**：各子应用模块（导入任务上报）
- **被依赖**：无

## 3. 状态机

### 3.1 任务状态流转（导入 / 导出共用）

```
[处理中(10)] ──{导入流程结束}──> [完成(20)]
```

| 当前状态 | 操作 | 目标状态 | 触发角色 | 校验条件 |
|---------|------|---------|---------|---------|
| (新建) | 发起任务（导入 / 导出） | 处理中(10) | 系统 / **财务提交导出** | — |
| 处理中(10) | 任务处理结束 | 完成(20) | 系统 | **导入**：流程结束（无论是否有失败数据）；**导出**：全部账单处理完毕（成功 + 失败 = 总数） |

> 状态仅单向流转（处理中→完成），**导入与导出共用**。失败数据通过 `fail_count` + 文件字段承载，不影响任务状态 —— **导入**用 `error_file_url`（错误明细，可修正后重导）；**导出**用 `result_file_url`（结果文件，含失败清单，无"重导"链路）。

## 5. 页面规格

### 5.1 后台任务（员工端 / 货主端）

**页面信息**：
- **路径**：一级菜单 > 后台任务
- **类型**：列表页
- **访问角色**：员工/运营（查看所有）、货主（查看本租户）

**搜索条件**：
- 任务编号（输入框，模糊搜索）
- 模块名称（输入框，模糊搜索）
- 任务状态（下拉：完成/处理中）

**操作按钮**：查询、重置

**列表页字段表**：

| 字段名 | 中文名 | 类型 | 数据来源 | 备注 |
|--------|--------|------|---------|------|
| task_no | 任务编号 | 文本 | import_task.task_no | EXP+年月日+时间戳 |
| module_name | 模块名称 | 文本 | import_task.module_name | 各菜单名，如"商品管理" |
| task_type | 任务类型 | 文本 | import_task.task_type | 导入 / **导出** |
| task_status | 任务状态 | 标签(el-tag) | import_task.task_status | 完成→success, 处理中→warning |
| task_result | 任务结果 | 文本 | 拼接字段 | **导入**："导入X条，失败Y条，成功Z条"；**导出**："导出X张账单（{模板分类}），成功Y张，失败Z张"；处理中显示"—" |
| creator | 创建人 | 文本 | import_task.creator | 员工端=员工姓名；货主端=客户公司名称 |
| created_at | 创建时间 | DateTime | import_task.created_at | — |
| finished_at | 完成时间 | DateTime | import_task.finished_at | 处理中显示"—" |
| operation | 操作 | 按钮 | — | **导入**：`fail_count>0` 显示"下载错误数据"；**导出**：完成后显示"下载导出结果" |

**交互行为**：
- [查询]：按任务编号/模块名称/任务状态筛选，点击"查询"执行搜索
- [重置]：清空所有搜索条件
- [下载错误数据]：**导入任务**、任务状态=完成 且 `fail_count>0` 时显示；点击下载错误结果文件
- [下载导出结果]：**导出任务**、任务状态=完成 且结果文件**未过保留期**时显示；点击下载结果文件（**一个 zip，内含 N 个账单 Excel**；1 张时直出 xlsx）
- [任务结果]：按任务类型拼接（见 §5.1 字段表）；处理中显示"—"

**关联接口**：
- 查询列表：`GET /api/import-tasks` (params: task_no, module_name, task_status, page, size)
- 下载错误数据（导入）：`GET /api/import-tasks/{id}/error-file`
- 下载导出结果（导出）：`GET /api/import-tasks/{id}/result-file`

### 5.2 导出任务（由财务「**账单管理 → 已发送 → 导出**」发起）

> 本模块**不产生**导出任务，只**承载**它：财务在账单管理里点「导出」→ 选模板分类（常规模板 / 出口退税模板）→ 提交 → 任务落本页，进度与结果文件都在这里看。导出侧的完整规格（入口位置、范围、交付粒度、模板字段）见**财务 PRD R71 / §5.11**。

**任务口径**

| 项 | 口径 |
|:---|:---|
| 任务类型 | **导出(20)** |
| 模块名称 | `账单管理` |
| 总数 | 本次导出的**账单张数**（= 提交时「已发送」Tab 列表里**勾选的账单张数**） |
| 成功 / 失败 | 成功 = 出文件成功的账单张数；失败 = 出文件失败的账单张数（成功 + 失败 = 总数） |
| 结果文件 | `result_file_url` —— **一个 zip 压缩包**，内含每张账单一个 Excel（**一张账单一个 Excel、不按客户合并**）。一条任务**只给一个下载入口**，不在任务行上堆 N 个下载按钮 |
| 结果文件命名 | zip = `账单导出_{模板分类}_{提交时间}.zip`；包内 = `{账单编号}_{客户名称}.xlsx`（客户名称含 `/ \ : * ? " < > \|` 时以 `_` 替换） |
| 只导出 1 张 | **不打包**：直接给 `{账单编号}_{客户名称}.xlsx`（省掉解压这一步） |
| 有失败时 | 包内除成功的 Excel 外，另附 **`导出失败清单.xlsx`**（账单号 / 客户 / 模板分类 / 失败原因）—— 保证"一次下载拿全" |
| 保留期 | **结果文件保留 7 天**；**任务记录长期保留**。过期后「下载导出结果」置灰 + 悬浮「结果文件已过期，请重新导出」（R09） |
| 任务结果文案 | `导出 {总数} 张账单（{模板分类}），成功 {成功} 张，失败 {失败} 张` |
| 操作列 | 任务完成 → 「**下载导出结果**」；**不显示「下载错误数据」**（导出没有"修正后重导"链路，失败清单在结果文件内） |
| 展示范围 | **只有员工端后台任务列表展示导出任务**；货主端不展示（R08） |
| 是否改变业务数据 | **不改** —— 导出是纯读动作，账单的发送 / 确认 / 核销 / 作废四个维度全不动 |

## 6. 业务规则

| 编号 | 触发点 | 条件/公式 | 输出 | 异常处理 |
|------|--------|----------|------|---------|
| R01 | 任务创建 | 任务编号 = "EXP" + 年月日(YYYYMMDD) + 时间戳 | 全局唯一 | — |
| R02 | 任务类型 | **导入(10) / 导出(20)**（2026-09-16 起支持导出，原"导出暂不监控"作废） | 列表显示"导入"/"导出" | 未知类型 → 按导入渲染 |
| R03 | 任务状态 | 仅"处理中"/"完成"；导入流程结束即"完成"（无论是否有失败数据） | 状态更新 | — |
| R04 | 任务结果 | 按类型拼接：导入 = `导入{total}条，失败{fail}条，成功{success}条`；导出 = `导出{total}张账单（{模板分类}），成功{success}张，失败{fail}张` | 列表拼接展示 | 处理中显示"—" |
| R05 | 操作列 | 导入：`fail_count > 0` 且 `error_file_url` 存在 → 「下载错误数据」；导出：任务完成且 `result_file_url` 存在 → 「下载导出结果」 | 显示对应按钮 | 不满足条件不显示按钮 |
| R07 | 导出任务的来源与范围 | 财务「账单管理 → 已发送」提交；范围 = 提交时该 Tab 列表里**勾选的账单**（**勾选前置**、可跨客户勾选、勾选仅对当前列表有效），**一张账单一个 Excel、不按客户合并**，模板分类由财务选 | 落一条导出任务 | **未勾选任何账单 → 财务侧阻断（400）**，不产生任务 |
| R08 | 导出任务的展示范围 | 导出是内部动作（对客凭证以"账单发送"为准） | **仅员工端可见导出类任务**；货主端不展示 | 货主端仍只按 tenant_id 看导入任务 |
| R09 | 导出结果文件的保留 | 任务完成后开始计时 | **结果文件保留 7 天**（**任务记录长期保留**，二者分开）；到期清理物理文件 | 过期后「下载导出结果」置灰 + 悬浮「结果文件已过期，请重新导出」；**重复下载不重置计时** |
| R06 | 数据隔离 | 员工端不过滤 tenant_id；货主端按 tenant_id 过滤 | 列表按角色过滤 | — |
