# 后台任务模块 — 产品文档

> **原始需求**：为飞点TMS搭建统一的**任务**监控模块（**导入 + 导出**），员工端和货主端均可查看各模块的任务结果 —— 导入任务下载错误数据，**导出任务下载结果文件**（导出任务由财务「账单管理 → 已发送 → 导出」发起，**只在员工端展示**）
> **文档版本**: v1.1 | **日期**: 2026-09-16 | **作者**: AI PM
> **数据来源**: 用户需求沟通
> **★ 文档分工（去哪看）**：字段结构/类型/约束/枚举值 → 数据设计 Schema；页面交互 → 原型。本文档 = 需求 + 业务规则（R 编号按流程分段）+ 状态机 + 功能清单 + 权限 + AC + 分期。

## 1. 核心洞察 (Insight)

**真实痛点**：

各子应用模块（商品管理、地址管理、港口管理等）均涉及 Excel 导入功能，但导入任务分散在各模块内，缺乏统一入口查看导入结果。当导入出现部分失败时，用户需要到各自模块查找失败原因，无法集中下载错误数据，排查效率低。

**JTBD**：

> `员工/运营` 雇佣"后台任务"不是为了"看列表"，而是为了：**当某个模块的导入任务跑完后，能在一个地方集中查看导入结果，若有失败数据可直接下载错误明细，不用逐个模块去翻。**

> `货主` 雇佣"后台任务"是为了：**提交导入后能及时看到处理进度和结果，失败时能下载错误数据修正后重导。**
>
> `财务专员` 看"后台任务"里的导出任务是为了：**导出是异步跑批**（一张账单一个 Excel，一次几十上百个文件）—— 点完不能干等页面，要能在一个地方看到「跑到哪了、成了几张」，完成后**一次把结果文件拿走**。

**业务价值**：

| 维度 | 当前 | 目标 |
|------|------|------|
| 导入结果查看 | 分散在各模块 | 统一后台任务列表 |
| 错误数据下载 | 无统一入口 | 一键下载错误明细 |
| 任务进度追踪 | 不可见 | 处理中/完成状态可见 |

## 2. 业务全景图

### 2.1 角色与工作节奏

| 角色 | 核心任务 | 频率 |
|------|---------|------|
| 员工/运营 | 查看所有模块的导入任务结果，下载错误数据 | 按需 |
| 货主 | 查看本企业的导入任务结果，下载错误数据 | 按需 |

### 2.2 端到端业务链路

```
【任务产生】各模块发起导入 → 生成导入任务（任务编号 EXP+年月日+时间戳）
      ↓
【任务处理】系统处理导入 → 任务状态=处理中
      ↓
【任务完成】导入流程结束 → 任务状态=完成（无论是否有失败数据）
      ↓
【结果查看】后台任务列表查看任务结果（导入X条，失败Y条，成功Z条）
      ↓
【错误下载】若有失败数据 → 下载错误数据 → 修正后重新导入
```

```
【任务产生】财务在「账单管理 → 已发送」提交导出 → 生成导出任务（同一编号规则）
      ↓
【任务处理】系统按所选模板分类逐张账单出 Excel → 任务状态=处理中
      ↓
【任务完成】全部账单处理完毕 → 任务状态=完成（成功张数 / 失败张数）
      ↓
【结果下载】下载导出结果（N 个账单 Excel 打包）—— 导出任务没有"错误数据修正后重导"这条链路
```

### 2.3 实体依赖关系

```
ImportTask (导入任务)
  └── 独立实体，公共模块，各子应用模块的导入任务统一记录
```

## 3. 流程：导入任务监控

> **触发**：各模块发起导入任务
> **频率**：按需
> **前置依赖**：各模块已接入导入任务上报

### 3.1 导入任务 (ImportTask) — 公共实体，记录各模块导入任务

| 字段 | 必填 | 说明 |
|------|------|------|
| task_no | ✅ | 任务编号，EXP + 年月日(8位) + 时间戳，如 EXP20260828143052123 |
| module_name | ✅ | 模块名称，各菜单名，如"商品管理""地址管理" |
| task_type | ✅ | 任务类型：10 **导入** / 20 **导出**（导出由财务「账单导出」发起、只在员工端展示） |
| task_status | ✅ | 任务状态：处理中 / 完成 |
| total_count | ✅ | 总数（导入 = 导入条数；导出 = 本次导出的**账单张数**） |
| success_count | ✅ | 成功数（导出 = 成功出文件的账单张数） |
| fail_count | ✅ | 失败数（导出 = 出文件失败的账单张数） |
| error_file_url | — | 错误结果文件URL，仅**导入**任务且 fail_count > 0 时有值 |
| result_file_url | — | **导出结果文件URL** = **一个 zip**（内含每张账单一个 Excel；**只勾 1 张时不打包、直出 xlsx**；有失败时包内另附「导出失败清单.xlsx」），仅**导出**任务完成时有值、**保留 7 天**；与 `error_file_url` 互斥使用 |
| creator | ✅ | 创建人。员工端=本公司员工姓名（如张三、李四）；货主端=客户公司名称（如拼多多有限公司）；**导出任务 = 提交导出的财务专员姓名** |
| created_at | ✅ | 创建时间，任务开始时间 |
| finished_at | — | 完成时间，任务完成时间（处理中为空） |

**业务规则**（权威编号见本文档「业务规则」章节）：
- 任务编号 = "EXP" + 年月日(YYYYMMDD) + 时间戳，全局唯一
- 任务类型 = **导入(10) / 导出(20)** —— 2026-09-16 起支持导出：财务「账单导出」提交的任务落本表并在此监控（原「导出暂不监控、后续用 BI 工具做」的口径作废）
- 任务状态仅"处理中"/"完成"两态；只要导入流程结束（无论是否有失败数据），状态即为"完成"
- 任务结果**按任务类型分支**，均由 total/success/fail 三字段拼接、处理中显示"—" —— **导入** = `导入{total}条，失败{fail}条，成功{success}条`；**导出** = `导出{total}张账单（{模板分类}），成功{success}张，失败{fail}张`
- 操作列**按任务类型分支** —— **导入**：`fail_count > 0` 时显示「下载错误数据」（下 `error_file_url`）；**导出**：任务完成后显示「**下载导出结果**」（下 `result_file_url`）。**导出任务不显示「下载错误数据」** —— 它的"失败"是"某几张账单出文件失败"，**没有"修正后重导"这条链路**，失败清单在结果文件里
- 员工端查看所有租户任务；货主端仅查看本租户任务（tenant_id 隔离）
- **导出任务的来源与范围** = 财务「账单管理 → 已发送」Tab 列表里**勾选的账单**（**必须先勾选**；可跨客户勾选；勾选仅对当前列表有效）；**一张账单一个 Excel、不按客户合并**；模板分类由财务在导出弹窗里选（常规模板 / 出口退税模板）—— 细节见财务产品文档 R2.12 / §5.11
- **导出任务不进租户视角** —— 导出是内部动作（对客凭证以"账单发送"为准），**货主端后台任务列表不展示导出类任务**

**相关 AC**：`AC01` `AC02` `AC03` `AC04` `AC05` `AC06` `AC07` `AC08`

## 需求定义

### 1.1 背景与现状

各子应用模块（商品管理、地址管理、港口管理等）均涉及 Excel 导入功能，但导入任务分散在各模块内，缺乏统一入口查看导入结果。当导入出现部分失败时，用户需要到各自模块查找失败原因，无法集中下载错误数据。

### 1.2 目标与成功口径

- **目标**：搭建统一的**任务**监控模块（导入 + 导出），员工端和货主端均可查看各模块任务结果 —— 导入任务下载错误数据，**导出任务下载结果文件**
- **成功口径**：导入任务统一可见、错误数据可一键下载；**导出任务提交后进度可见、结果文件可一键下载**（导出任务的**来源与范围**见 §5.2 / R07）

### 1.3 范围与边界

**In Scope（本期 P0）**：
- 后台任务列表（任务编号/模块名称/任务类型/状态/结果/创建人/时间）
- 搜索（任务编号/模块名称/任务状态）
- 下载错误数据（导入任务、fail_count > 0 时）
- **导出任务监控与结果下载**（2026-09-16 新增：财务「账单管理 → 已发送 → 导出」提交的任务落本模块，完成后可下载结果文件）

**Out of Scope**：
- ~~导出任务监控~~ —— **已纳入本期**（原「后续用 BI 工具做导出、无需监控」的口径作废）
- 任务重试/取消
- 任务详情页

### 1.4 影响范围

- **影响角色**：员工/运营、货主
- **依赖系统**：各子应用模块（导入任务上报）
- **被依赖**：无

## 状态机 ★ 研发必读

### 1 任务状态流转（导入 / 导出共用）

```
[处理中(10)] ──{导入流程结束}──> [完成(20)]
```

| 当前状态 | 操作 | 目标状态 | 触发角色 | 校验条件 |
|---------|------|---------|---------|---------|
| (新建) | 发起任务（导入 / 导出） | 处理中(10) | 系统 / **财务提交导出** | — |
| 处理中(10) | 任务处理结束 | 完成(20) | 系统 | **导入**：流程结束（无论是否有失败数据）；**导出**：全部账单处理完毕（成功 + 失败 = 总数） |

> 状态仅单向流转（处理中→完成），**导入与导出共用**。失败数据通过 `fail_count` + 文件字段承载，不影响任务状态 —— **导入**用 `error_file_url`（错误明细，可修正后重导）；**导出**用 `result_file_url`（结果文件，含失败清单，无"重导"链路）。

| R1.9 | 数据隔离 | 员工端不过滤 tenant_id；货主端按 tenant_id 过滤 | 列表按角色过滤 | — |
