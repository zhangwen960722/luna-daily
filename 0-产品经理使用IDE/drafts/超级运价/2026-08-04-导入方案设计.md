# 成本 & 加成额 Excel 导入 — 方案设计

> 日期: 2026-08-04 | 状态: 方案定稿 | 关联: RDD §5.9 + §7.5

---

## 1. 背景与问题

### 1.1 为什么要导入

运价管理员每周维护 140+ 服务组合的成本与加成额，当前只能在工作台矩阵中逐行手工编辑。船公司/代理周一发来新报价 Excel 后，管理员需要在系统中逐条更新，30 分钟全量更新的 JTBD 无法完成。

### 1.2 当前设计缺陷

导入模板缺少**"服务组合"维度**。模板仅标识"改哪个成本项"（通过成本项名称 / 交货地组 / 渠道+仓点等匹配键），但同一成本项在不同服务组合中可能有不同价格：

- 例：海运费在"美森360-普货-散货"是 $3.50/KG，在"美森360-敏感货-散货"是 $4.00/KG
- 当前方案：管理员需筛选组合 → 导入 → 再筛选 → 再导入，重复 N 次
- 期望方案：一个 Excel 包含所有 (成本项, 组合) 行，一次导入搞定

### 1.3 入口

所有导入统一在工作台批次栏操作，不在成本管理 / 服务渠道 / 服务组合中分散入口。

---

## 2. 总体设计

### 2.1 核心思路

**所有成本导入模板统一增加"服务组合"列**，支持两种语义：

| 服务组合填值 | 语义 | 更新目标 |
|:---|:---|:---|
| `全部` | 更新上游源记录（模板/渠道配置/交货地组），影响所有引用该源的下游组合 | 源表默认值 |
| 具体组合名称 | 仅更新该组合的成本覆盖值，不影响其他组合 | 组合级覆盖值 |

同一成本项可出现在模板多行，每行指定不同组合 → 一次导入覆盖所有差异化定价。

### 2.2 通用规则

- **空单元格 = 不更新**：新值列为空则该字段保持不变
- **按匹配键定位**：匹配不到的行跳过，在导入报告中标注"未匹配"
- **不新增不删除**：仅更新已有记录，不创建新成本项 / 新组合
- **事务策略**：≤50 行单事务；>50 行分批提交（50 行/批），失败批次回滚并在报告中标红
- **下载模板 = 当前值快照**：模板按匹配键展开全部现有行，预填所有当前值，运价管理员仅需修改变化的单元格
- **导入后联动**：更新完成后自动触发成本重算（R08/D0a 传播链）→ 标记受影响运价行"待复核"

### 2.3 匹配与覆盖优先级

当同一 (成本项, 组合) 在导入文件中出现多行时，最后一行生效。导入文件中的"全部"行和"具体组合"行同时存在时：

- "具体组合"行 > "全部"行（组合级覆盖优先于源表默认值）
- 具体组合的覆盖值更新到组合级；"全部"的值更新到源表默认值
- 若某组合在导入文件中无对应行 → 该组合的成本保持不变（沿用源表默认值或已有覆盖值）

## 3. 各导入类型模板字段

### 3.1 普通成本项导入

**更新链路**：
- 服务组合 = `全部` → 更新 `cost_item_template.default_price` → R08 传播到全部渠道 → 全部组合
- 服务组合 = 具体 → 更新该组合的普通成本项覆盖值（组合级）

| # | 列名 | 说明 | 可编辑 | 匹配键 |
|:---|:---|:---|:---:|:---|
| 1 | 成本段 | `cost_segment.name` | ❌ | ✅ |
| 2 | 成本项名称 | `cost_item_template.name` | ❌ | ✅ |
| 3 | **服务组合** | `全部` 或 `combination_code` | ❌ | ✅ |
| 4 | 币种 | 当前币种，供参考 | ❌ | |
| 5 | 当前价 | 当前生效值（源表默认或组合覆盖值） | ❌ | |
| 6 | 新价 | 填入新价格 | ✅ | |

**模板行数**：N 个普通成本项 × M 个引用该成本项的组合（含"全部"快捷行）
**预置项排除**：拖车费（预置）、卡派仓点成本（预置）、快递派单价（预置）不出现在此模板中

**示例**：

| 成本段 | 成本项名称 | 服务组合 | 币种 | 当前价 | 新价 |
|:---|:---|:---|:---|:---|:---|
| 干线运输段 | 海运费 | 全部 | USD | 3.50 | 3.80 |
| 干线运输段 | 海运费 | 美森360-普货-散货 | USD | 3.50 | 4.00 |
| 干线运输段 | 文件费 | 全部 | RMB | 200.00 | |
| 揽收段 | 装柜费 | 全部 | RMB | 1.50 | 1.60 |

> 第 1 行：海运费默认价涨到 $3.80，影响所有组合（除第 2 行覆盖的）
> 第 2 行：仅"美森360-普货-散货"覆盖为 $4.00
> 第 3 行：文件费不改（新价留空）
> 第 4 行：装柜费默认价涨到 $1.60

### 3.2 拖车费导入

**更新链路**：
- 服务组合 = `全部` → 更新 `delivery_group.truck_fee` / `sc_rmb` → 所有引用该交货地组的组合
- 服务组合 = 具体 → 更新该组合的拖车费覆盖值（组合级）

| # | 列名 | 说明 | 可编辑 | 匹配键 |
|:---|:---|:---|:---:|:---|
| 1 | 交货地组 | `delivery_group.name` | ❌ | ✅ |
| 2 | **服务组合** | `全部` 或 `combination_code` | ❌ | ✅ |
| 3 | 包含交货地 | `delivery_group.regions`，供参考 | ❌ | |
| 4 | 当前拖车费单价 | `truck_fee` 当前值 | ❌ | |
| 5 | 当前加价 | `sc_rmb` 当前值 | ❌ | |
| 6 | 新拖车费单价 | 更新值 | ✅ | |
| 7 | 新加价 | 更新值 | ✅ | |

**模板行数**：N 个交货地组 × M 个关联组合（含"全部"快捷行）

**示例**：

| 交货地组 | 服务组合 | 包含交货地 | 当前单价 | 当前加价 | 新单价 | 新加价 |
|:---|:---|:---|:---|:---|:---|:---|
| 珠三角 | 全部 | 深圳,广州,东莞 | 1200.00 | 0.00 | 1300.00 | |
| 义乌 | 全部 | 义乌 | 1700.00 | 50.00 | | |

### 3.3 卡派仓点成本导入

**更新链路**：
- 服务组合 = `全部` → 更新 `渠道.派送仓点成本`（三种报价）→ D0a 传播到全部引用该渠道的组合
- 服务组合 = 具体 → 更新该组合的派送仓点成本覆盖值（组合级）

| # | 列名 | 说明 | 可编辑 | 匹配键 |
|:---|:---|:---|:---:|:---|
| 1 | 渠道名称 | `service_channel.name` | ❌ | ✅ |
| 2 | 服务类型 | 散货 / 整柜 | ❌ | ✅ |
| 3 | **服务组合** | `全部` 或 `combination_code` | ❌ | ✅ |
| 4 | FBA仓点 | 单个仓点代码 | ❌ | ✅ |
| 5 | 币种 | 当前币种 | ❌ | |
| 6 | 当前-拆送价 | 当前值（`—` = 未填） | ❌ | |
| 7 | 当前-一口价 | 当前值 | ❌ | |
| 8 | 当前-直送价 | 当前值 | ❌ | |
| 9 | 新-拆送价 | 至少填一种报价方式 | ✅ | |
| 10 | 新-一口价 | | ✅ | |
| 11 | 新-直送价 | | ✅ | |

> 数据设计中 `fba_warehouse_codes` 是数组（同行多仓点同价合并）。导入 Excel 每行一个仓点，系统自动处理合并/拆行。

**模板行数**：N 个 (渠道 × 服务类型 × FBA仓点) × M 个关联组合（含"全部"快捷行）

### 3.4 快递派单价导入

**更新链路**：
- 服务组合 = `全部` → 更新 `渠道.快递派送单价` → D0a 传播到全部引用该渠道的组合
- 服务组合 = 具体 → 更新该组合的快递派送单价覆盖值（组合级）

| # | 列名 | 说明 | 可编辑 | 匹配键 |
|:---|:---|:---|:---:|:---|
| 1 | 渠道名称 | `service_channel.name` | ❌ | ✅ |
| 2 | **服务组合** | `全部` 或 `combination_code` | ❌ | ✅ |
| 3 | 重量段 | `weight_tier.tier_name`（如 `1KG+`） | ❌ | ✅ |
| 4 | 邮编前缀 | `zip_prefixes` | ❌ | ✅ |
| 5 | 币种 | 当前币种 | ❌ | |
| 6 | 当前单价 | 当前值 | ❌ | |
| 7 | 新单价 | 更新值 | ✅ | |

**模板行数**：N 个 (渠道 × 重量段 × 邮编前缀) × M 个关联组合（含"全部"快捷行）

### 3.5 加成额导入

**更新目标**：`price_table_row.markup`（组合 × 重量段 × 交货地组 × 计价单位的加成额）
**联动**：`公布价 = 成本底价 + 新加成额`（KG 和 m³ 独立计算）

加成额本身已是组合级数据，匹配键已包含组合名称，**无需额外增加"服务组合"列**。

| # | 列名 | 说明 | 可编辑 | 匹配键 |
|:---|:---|:---|:---:|:---|
| 1 | 组合名称 | `combination_code` | ❌ | ✅ |
| 2 | 仓库组 / 邮编 | 卡派 = 仓库组，快递派 = `zip_prefixes` | ❌ | ✅ |
| 3 | 重量段 | `weight_tier.tier_name` | ❌ | ✅ |
| 4 | 交货地组 | `delivery_group.name`（`—` = 不适用） | ❌ | ✅ |
| 5 | 当前加成额-KG | 当前值（`—` = 不适用） | ❌ | |
| 6 | 当前加成额-m³ | 当前值 | ❌ | |
| 7 | 新加成额-KG | 仅计费方式含 KG 的组合可填 | ✅ | |
| 8 | 新加成额-m³ | 仅计费方式含 m³ 的组合可填 | ✅ | |

**校验**：导入后校验——计费方式含 KG 的组合加成额-KG 必填，含 m³ 的组合加成额-m³ 必填。

## 4. 处理流程

### 4.1 整体流程

```
下载模板（预填当前值）
    → 运价管理员填新价格
    → 上传 Excel
    → 系统解析 + 校验（格式/匹配键/数值合法性）
    → 预览变更清单（标记变更行 + 受影响组合）
    → 运价管理员确认
    → 执行更新：
        1. 按 (匹配键 + 服务组合) 定位记录
        2. "全部" → 更新源表默认值
        3. 具体组合 → 更新组合级覆盖值
        4. 空单元格跳过
        5. 未匹配行写入导入报告
    → 触发传播链（R08 / D0a）
    → 标记受影响运价行"待复核"
    → 生成导入结果报告
```

### 4.2 校验规则

| 校验项 | 规则 | 违规处理 |
|:---|:---|:---|
| 必填匹配键 | 匹配键列不得为空 | 跳过该行，报告标注 |
| 数值合法性 | 新价格必须 ≥ 0，最多 2 位小数 | 跳过该行，报告标注 |
| 组合存在性 | 具体组合名称必须在系统中存在 | 跳过该行，报告标注 |
| 至少一个变更 | 每行至少一个新值列非空 | 无变更行保留原值不报错 |
| 预置项保护 | 预置成本项（拖车费/仓点成本/快递派单价）不在普通成本项模板中出现 | 模板生成时自动排除 |

### 4.3 导入报告

导入完成后生成报告，包含：
- **成功**：N 行已更新，影响 M 个运价行
- **跳过**：K 行无变更（新值全部为空）
- **未匹配**：X 行匹配键在系统中不存在（列出具体行号 + 匹配键值）
- **错误**：Y 行校验失败（列出具体行号 + 原因）
