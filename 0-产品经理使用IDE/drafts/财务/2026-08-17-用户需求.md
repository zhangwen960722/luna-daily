# 需求定义卡片 (RDD) — 财务模块

> **原始需求**：财务是多主体独立核算 + 钱进钱出闭环，消费订单/运单数据
> **文档版本**: v0.1（对齐稿，待细化）| **日期**: 2026-08-17 | **作者**: 飞点产品

## 1. 核心洞察

### 1.1 模块定位（消费方）

- 订单/运单是**独立模块**，财务只消费其数据，不碰下单、履约
- 财务职责 = 多主体独立核算 + 钱进钱出闭环 + 资金账户
- 唯一计费触发点：**运单收货完成**

### 1.2 组织架构（2 租户 5 账套）

| 层 | 作用 | 数量 |
|:---|:---|:---|
| 租户 | 数据隔离 | 2（飞点、墨链） |
| 账套（主体） | 独立核算 | 5（广州飞点、深圳飞点、广东飞点、香港富利顿、墨链） |

- 5 家公司税务上独立法人，实际一个家族
- 硬规则：每笔钱挂具体主体，客户打款不可跨主体混打

### 1.3 计费口径

运单收货完成时，取「当周运价」：

- 运费 = 公布价；运费优惠 = 运价优惠规则
- 附加费 = 附加费规则；附加费优惠 = 附加费优惠
- 成本预估 = 服务组合当周成本（底价，未优惠）

## 3. 应收管理 · 细分（当前聚焦）

### 3.1 功能拆解

| 编号 | 功能点 | 说明 |
|:---|:---|:---|
| R1 | 业务流水生成 | 运单收货完成自动生成逐票流水（粒度=运单） |
| R2 | 账单生成 | 财务手工触发，按客户+主体+账期+币种聚合 |
| R3 | 账单确认（双锁） | 业务审计 → 财务审计 → 锁定 |
| R4 | 收款核销 | 客户打款按主体核销账单 |
| R5 | 账龄台账 | 未收余额 + 账龄 |

### 3.2 业务流水 → 账单（两层）

```
运单收货完成 → 应收业务流水（逐票、自动、粒度=运单）
                    ↓ 财务手工触发，按 客户+主体+账期+币种 聚合
             账单（账期级，汇总多票流水）
```

- **账期**：消费客商中心 `customer_contract` 表（合同级，跟随合同不跟随客户），财务不重复维护。字段：账单周期（固定/不固定）+ 签约账期（月结/双月结/三月结/周结/到港前结/签收月结/到海外仓结/签收结）+ 结算类型（按月/按天自动推导）+ 结算月 + 天数/号
- **账单粒度**：账单号挂在每条业务流水上（流水级字段）。一个运单的多条流水按「币种 + 账期」拆到多个账单，可跨期、跨年

### 3.3 双锁审计 + 纠错规则

**审计分两层**：

- 运单级审计：控制"能否新增业务流水"
- 业务流水级审计：控制"能否修改该条流水"

```
[待业务审计] --业务审计通过--> [待财务审计] --财务审计通过--> [已锁定]
     ↑驳回                          ↑驳回
  退回修改                       退回修改
```

- 财务审计通过后，运单应收业务流水不可再动
- **正向双锁角色**：业务添加确认后做业务侧审计（运单+流水）→ 财务做财务侧审计（运单+流水），双审计通过才锁定
- **反审计权限**：只有财务能执行反审计；业务要反审计，通过工单系统提交需求或线下找财务沟通

**反审计操作（财务触发，以"是否关联账单"为分界）**：

| 财务操作 | 前提 | 业务侧可做什么 |
|:---|:---|:---|
| 反审计运单 | — | 新增业务流水 |
| 反审计运单 + 反审计某条流水 | 该流水未关联账单 | 修改该条流水（改完重新审计） |
| （流水已关联账单） | 不可反审计 | 只能红冲 |

**红冲规则**：原流水留痕不动 → 反审计运单 → 新增负数流水（−原值）+ 正数流水（+新值），净额 = 调整差额；红冲新增的两条流水归入**下一期账单**。

## 4. 关键业务规则

- 汇率三层：实时基准 + 手工覆盖 + 入账快照锁定
- 客户资金账户 = 预存款钱包，与支付渠道解耦（未来在线付款只加渠道）

## 5. 已确认 + 待确认

### 已确认

1. 账期：在客商中心 `customer_contract` 表（合同级），财务消费不重复维护
2. 账期类型：账单周期（固定/不固定）+ 签约账期（月结/双月结/三月结/周结/到港前结/签收月结/到海外仓结/签收结）
3. 纠错：未生成账单→反审计后直改；已生成账单→只能红冲
