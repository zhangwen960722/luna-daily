# Workflow: Phase 4 - 验证与迭代 (Verify & Iterate)

此工作流用于**质量保证阶段**。产品文档与原型输出不是终点，验证通过才能交付。

**输入**: 全部交付物 — 需求背景 + 产品文档 + 数据设计 + 原型

> **模块聚焦**：验证默认限定当前模块的 4 份文档链路。若用户要求跨模块验证，按 AGENTS.md §工作模式判断 扩展范围。

## 步骤 1: 文档链路一致性检查 (Document Chain Verification)

> **Goal**: 按文档链路逐组对照，确保 4 份文档之间逻辑闭环、数据一致、无遗漏无矛盾。

### 1. 需求背景 ↔ 产品文档

- [ ] 产品文档的核心洞察是否回应了需求背景中记录的原始痛点？方向是否跑偏？
- [ ] 需求背景中提到的约束条件（时间/资源/技术栈）是否在产品文档的 NFR 或 MVP 方案中体现？

### 2. 产品文档 ↔ 数据设计

- [ ] 产品文档的实体字段表是否在数据设计中都有对应（表/子表/JSON 字段/纯逻辑实体）？
- [ ] 产品文档的业务规则（R 编号）是否在数据设计中通过约束/索引/状态机得到支撑？
- [ ] 实体数量是否对齐？（产品文档有 N 个实体 → 数据设计有 N 个表映射）
- [ ] 产品文档的状态机与数据设计状态流转定义一致？

### 3. 产品文档 ↔ 原型（如有）

**文档对齐**（产品文档功能清单 vs 原型实现）：
- [ ] 页面覆盖 — 产品文档 §5 功能清单每个功能点是否有对应页面（原型链接有效）？
- [ ] 数据模型对齐 — 字段标签/类型/实体数量是否与数据设计一致？
- [ ] 按钮行为 — 新增/编辑/删除/冻结是否真实操作数据？
- [ ] 必填校验/筛选搜索 — 是否生效？
- [ ] 异常状态 — 空状态/无匹配/错误提示是否覆盖？
- [ ] 冻结只读 + 状态二次确认 — 是否符合约定？

**前端规范**（对照 frontend-designer §必须遵守的约束 + §弹窗模板 + §表格列宽规范 逐项检查，不再逐条在此重复）

### 4. 全局检查

- [ ] 状态流转是否闭环？（正向+逆向+异常路径均覆盖）
- [ ] 敏感数据是否脱敏？（手机号、身份证）
- [ ] 权限矩阵是否覆盖所有角色？
- [ ] 所有文档的模块名、日期、版本号是否一致？

## 步骤 2: 问题回溯 (Backtracking)

> **Goal**: 如果发现问题，回到对应阶段修正。

根据问题类型，回到对应 Workflow：

| 问题类型         | 回到阶段        | 示例                           |
| :--------------- | :-------------- | :----------------------------- |
| **需求理解错误** | Phase 1         | 发现做的不是用户真实痛点       |
| **业务规则缺陷** | Phase 1         | 规则编号分段错、校验逻辑漏     |
| **数据模型缺陷** | Phase 2 - 步骤1 | ER关系设计错误，缺少关键字段   |
| **边界情况遗漏** | Phase 2 - 步骤2 | 并发场景未覆盖，状态机有死循环 |
| **IA设计问题**   | Phase 2 - 步骤4 | 菜单层级不合理、页面遗漏       |
| **外部接口遗漏** | Phase 2 - 步骤3 | 缺少外部模块的接口依赖清单     |
| **原型实现问题** | Phase 3 - 步骤2 | 弹窗组件错误、交互不符合规范   |

**修正后，必须重新执行本阶段（Phase 4）验证**。

## 步骤 3: 最终交付 (Delivery)

> **Goal**: 确认无误后，正式归档。

1. 产品文档留在模块目录 `drafts/[模块名]/`，日期前缀标记为定稿日期。
2. 验收标准（AC）在产品文档 §10，供测试直接引用（不需另出 AC List）。
3. 变更记录追加遵循 AGENTS.md §修改后自检。

## 步骤 4: 用户确认 (User Confirmation)

询问用户：

1. 产品文档是否符合预期？是否需要调整？
2. 原型（如有）是否需要优化？
3. 是否可以正式交付给开发团队？

**Done**: 任务完成，进入开发排期！
