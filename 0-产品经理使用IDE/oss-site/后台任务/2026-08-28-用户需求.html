需求定义卡片 (RDD) — 后台任务

原始需求：为飞点TMS搭建统一的导入任务监控模块，员工端和货主端均可查看各模块的导入任务结果，下载错误数据 文档版本: v1.0 | 日期: 2026-08-28 | 作者: AI PM 数据来源: 用户需求沟通

1. 核心洞察 (Insight)

真实痛点：

各子应用模块（商品管理、地址管理、港口管理等）均涉及 Excel 导入功能，但导入任务分散在各模块内，缺乏统一入口查看导入结果。当导入出现部分失败时，用户需要到各自模块查找失败原因，无法集中下载错误数据，排查效率低。

JTBD：

员工/运营 雇佣"后台任务"不是为了"看列表"，而是为了：当某个模块的导入任务跑完后，能在一个地方集中查看导入结果，若有失败数据可直接下载错误明细，不用逐个模块去翻。

货主 雇佣"后台任务"是为了：提交导入后能及时看到处理进度和结果，失败时能下载错误数据修正后重导。

业务价值：

维度当前目标
------------------
导入结果查看分散在各模块统一后台任务列表
错误数据下载无统一入口一键下载错误明细
任务进度追踪不可见处理中/完成状态可见

2. 业务全景图

2.1 角色与工作节奏

角色核心任务频率
---------------------
员工/运营查看所有模块的导入任务结果，下载错误数据按需
货主查看本企业的导入任务结果，下载错误数据按需

2.2 端到端业务链路

`` 【任务产生】各模块发起导入 → 生成导入任务（任务编号 EXP+年月日+时间戳） ↓ 【任务处理】系统处理导入 → 任务状态=处理中 ↓ 【任务完成】导入流程结束 → 任务状态=完成（无论是否有失败数据） ↓ 【结果查看】后台任务列表查看任务结果（导入X条，失败Y条，成功Z条） ↓ 【错误下载】若有失败数据 → 下载错误数据 → 修正后重新导入 `

2.3 实体依赖关系

` ImportTask (导入任务) └── 独立实体，公共模块，各子应用模块的导入任务统一记录 `

3. 流程：导入任务监控

触发：各模块发起导入任务 频率：按需 前置依赖：各模块已接入导入任务上报

3.1 导入任务 (ImportTask) — 公共实体，记录各模块导入任务

字段类型必填说明
------------------------
task_no文本✅任务编号，EXP + 年月日(8位) + 时间戳，如 EXP20260828143052123
module_name文本✅模块名称，各菜单名，如"商品管理""地址管理"
task_type枚举✅任务类型，默认"导入"（导出暂不监控）
task_status枚举✅任务状态：处理中 / 完成
total_countInt✅导入总数
success_countInt✅成功数
fail_countInt✅失败数
error_file_url文本—错误结果文件URL，仅 fail_count > 0 时有值
creator文本✅创建人。员工端=本公司员工姓名（如张三、李四）；货主端=客户公司名称（如拼多多有限公司）
created_atDateTime✅创建时间，任务开始时间
finished_atDateTime—完成时间，任务完成时间（处理中为空）
业务规则：
  • R01：任务编号 = "EXP" + 年月日(YYYYMMDD) + 时间戳，全局唯一
  • R02：任务类型默认"导入"；导出暂不监控（后续用 BI 工具做导出，无需在此监控）
  • R03：任务状态仅"处理中"/"完成"两态；只要导入流程结束（无论是否有失败数据），状态即为"完成"
  • R04：任务结果 = "导入{total}条，失败{fail}条，成功{success}条"，由 total/success/fail 三字段拼接；处理中显示"—"
  • R05：操作列仅当 fail_count > 0 时显示"下载错误数据"，可下载错误结果文件；无失败数据不显示
  • R06：员工端查看所有租户任务；货主端仅查看本租户任务（tenant_id 隔离）
相关 AC：AC01 AC02 AC03 AC04 AC05 AC06 AC07

4. 验收标准总览 (AC)

  • [ ] AC01-任务列表展示：列表含任务编号、模块名称、任务类型、任务状态、任务结果、创建人、创建时间、完成时间、操作 9 列
  • [ ] AC02-任务编号格式：任务编号以 EXP 开头 + 年月日 + 时间戳，全局唯一
  • [ ] AC03-任务状态展示：完成→success标签，处理中→warning标签；完成时间在"处理中"时显示"—"
  • [ ] AC04-任务结果展示：完成任务显示"导入X条，失败Y条，成功Z条"；处理中显示"—"
  • [ ] AC05-下载错误数据：fail_count > 0 的任务操作列显示"下载错误数据"，点击可下载；无失败数据不显示按钮
  • [ ] AC06-搜索：支持按任务编号（模糊）、模块名称（模糊）、任务状态（下拉）搜索；重置清空条件
  • [ ] AC07-数据隔离：员工端查看所有任务；货主端仅查看本租户任务

5. NFR（非功能性需求）

  • 性能：列表查询 < 1s
  • 并发：同时操作员工数 ≤ 50
  • 数据保留：任务记录长期保留
  • 安全：货主端 tenant_id 隔离，仅查看本租户任务

7. MVP 方案与建议

MVP 方案（Phase 1 — 后台任务监控）

` 员工端 / 货主端 └── 后台任务（一级菜单） ├── 任务列表（任务编号/模块名称/任务类型/状态/结果/创建人/时间） ├── 搜索（任务编号/模块名称/任务状态） └── 下载错误数据（fail_count > 0 时） ``

MVP 明确不做：

  • 导出任务监控（后续用 BI 工具做导出，无需监控）
  • 任务重试/取消
  • 任务详情页
专家建议：
  • S01 — 任务编号全局唯一：EXP + 年月日 + 时间戳（精确到毫秒）保证全局唯一，时间戳精确到毫秒避免并发冲突
  • S02 — 状态简化：任务状态仅"处理中/完成"两态，不区分"部分失败"（只要流程结束即为完成），失败信息通过 fail_count + 错误文件承载
  • S03 — 公共模块解耦：后台任务作为公共模块，各子应用通过统一接口上报导入任务，避免与业务模块耦合
