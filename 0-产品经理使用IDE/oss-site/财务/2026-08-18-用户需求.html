需求定义卡片 (RDD) — 财务模块

原始需求：财务是多主体独立核算 + 钱进钱出闭环，消费订单/运单数据 文档版本: v0.2（对齐稿，应收管理 R1-R5 已细化）| 日期: 2026-08-18 | 作者: 飞点产品

1. 核心洞察

1.1 模块定位（消费方）

  • 订单/运单是独立模块，财务只消费其数据，不碰下单、履约
  • 财务职责 = 多主体独立核算 + 钱进钱出闭环 + 资金账户
  • 唯一计费触发点：运单收货完成

1.2 组织架构（2 租户 5 账套）

层作用数量
:---:---:---
租户数据隔离2（飞点、墨链）
账套（主体）独立核算5（广州飞点、深圳飞点、广东飞点、香港富利顿、墨链）
  • 5 家公司税务上独立法人，实际一个家族
  • 硬规则：每笔钱挂具体主体，客户打款不可跨主体混打

1.3 计费口径

运单收货完成时，取「当周运价」：

  • 运费 = 公布价；运费优惠 = 运价优惠规则
  • 附加费 = 附加费规则；附加费优惠 = 附加费优惠
  • 成本预估 = 服务组合当周成本（底价，未优惠）

3. 应收管理 · 细分（R1-R5 已对齐）

3.1 功能拆解

编号功能点说明
:---:---:---
R1业务流水生成运单收货完成自动生成逐票流水（粒度=运单）
R2账单生成财务手工触发，按客户+主体+账期+币种聚合
R3账单确认（双锁）业务审计 → 财务审计 → 锁定
R4收款核销客户打款进预存款钱包，按账单核销
R5账龄台账未收余额 + 账龄（未到期 + 逾期四段）

3.2 业务流水 → 账单（两层）

`` 运单收货完成 → 应收业务流水（逐票、自动、粒度=运单） ↓ 财务手工触发，按 客户+主体+账期+币种 聚合 账单（账期级，汇总多票流水） `

  • 账期：消费客商中心 customer_contract 表（合同级，跟随合同不跟随客户），财务不重复维护。字段：账单周期（固定/不固定）+ 签约账期（月结/双月结/三月结/周结/到港前结/签收月结/到海外仓结/签收结）+ 结算类型（按月/按天自动推导）+ 结算月 + 天数/号
  • 账单粒度：账单号挂在每条业务流水上（流水级字段）。一个运单的多条流水按「币种 + 账期」拆到多个账单，可跨期、跨年

3.3 双锁审计 + 纠错规则

审计分两层：

  • 运单级审计：控制"能否新增业务流水"
  • 业务流水级审计：控制"能否修改该条流水"
` [待业务审计] --业务审计通过--> [待财务审计] --财务审计通过--> [已锁定] ↑驳回 ↑驳回 退回修改 退回修改 `

  • 财务审计通过后，运单应收业务流水不可再动
  • 正向双锁角色：业务添加确认后做业务侧审计（运单+流水）→ 财务做财务侧审计（运单+流水），双审计通过才锁定
  • 反审计权限：只有财务能执行反审计；业务要反审计，通过工单系统提交需求或线下找财务沟通
反审计操作（财务触发，以"是否关联账单"为分界）：

财务操作前提业务侧可做什么
:---:---:---
反审计运单—新增业务流水
反审计运单 + 反审计某条流水该流水未关联账单修改该条流水（改完重新审计）
（流水已关联账单）不可反审计只能红冲
红冲规则：原流水留痕不动 → 反审计运单 → 新增负数流水（−原值）+ 正数流水（+新值），净额 = 调整差额；红冲新增的两条流水归入下一期账单。

3.4 收款核销（R4）

核心链路：

` 客户打款 → 预存款钱包（分币种余额 +） ↓ 财务手工核销（从钱包扣款冲账单） 应收账单（未收余额 −） ↓ 多打 → 留钱包余额；少打 → 留未收进账龄 `

决策点：

决策点结论
:---:---
钱的池子客户打款统一进预存款钱包；每客户都有钱包，入驻成功自动开通默认钱包（联动入驻流程）
核销方式一期财务手工核销；二期自动核销
核销粒度池化模型，支持部分核销 / 一对多 / 多对一；不做进账↔账单映射（在线付款上线后再做关系表）
币种强制同币种，跨币种先走钱包互转
核销金额min(账单未收, 钱包余额)，钱包不可透支
核销结果多打留钱包余额；少打留未收进账龄
反核销支持；一期不接做账系统，未做账账单均可反核销；不加审批；留"核销/反核销日志"

3.5 账龄台账（R5）

起算口径：

  • 账单日 D、账期 N 天 → 账期内 = D～D+N−1（含账单日），最后支付日 = D+N−1，逾期第 1 天 = D+N
  • 例：账单日 1 号、账期 15 天 → 1～15 号账期内，15 号最后支付日，16 号逾期第 1 天
分段：未到期（单列）+ 逾期 0-30 / 31-60 / 61-90 / 90+

维度：客户 × 主体 × 币种

币种：分列，不折算（不做汇率折算混总）

4. 关键业务规则

  • 汇率三层：实时基准 + 手工覆盖 + 入账快照锁定
  • 客户资金账户 = 预存款钱包，与支付渠道解耦（未来在线付款只加渠道）
  • 钱包池化：钱进池子即混同，只认币种余额，不追来源进账

5. 已确认 + 待确认

已确认

1. 账期：在客商中心 customer_contract` 表（合同级），财务消费不重复维护 2. 账期类型：账单周期（固定/不固定）+ 签约账期（月结/双月结/三月结/周结/到港前结/签收月结/到海外仓结/签收结） 3. 纠错：未生成账单→反审计后直改；已生成账单→只能红冲 4. 收款核销：钱包池化 + 手工核销 + 部分核销 + 强制同币种 + 反核销（未做账可反） 5. 账龄：账单日 + 账期天数（含首日）起算，未到期单列 + 逾期四段，客户×主体×币种三维度

待确认

1. 应付、资金账户、对账中心、毛利分析细节待展开 2. 入驻流程自动开通默认钱包账户（联动入驻模块，实现方式待定） 3. 在线付款上线后，核销关系表设计（未来演进）
