2.7 运单级补充字段（供财务账单明细引用）

本节只登记被其他模块（财务「账单管理 → 账单详情」明细表）引用的运单级补充字段；运单主表字段全集以运单管理原型 demo/员工端-demo/Waybill.html 与财务 PRD §5.1 列表列为准，本节不重复登记、不代表运单主表全量设计。 本模块不持有运单数据（见 §4.4 纯逻辑实体说明），下表字段挂在运单（Waybill）实体上、随运单主表落库，头程管理侧不新增表，仅登记字段口径供财务账单明细引用。

箱级 vs 运单级（务必区分，研发不得混用）

运单管理原型 demo/员工端-demo/Waybill.html L3557-3562 的「编辑快递单」弹窗是按货箱维护的，列为：系统箱号 sysNo / 扩展箱号 extNo / 承运商代码 / 转单号 transferNo —— 一个运单多个货箱则多行，每行描述一个箱。本节登记的是运单级字段（一个运单一条值）：

对比项箱级（原型「编辑快递单」弹窗）运单级（本节登记，供财务账单明细引用）
:---:---:---
字段sysNo 系统箱号 / extNo 扩展箱号 / 承运商代码 / transferNo 转单号fba_no FBA 单号 / transfer_no 转单号 / product_qty 产品数量
粒度1 运单 : N 货箱，逐箱填写1 运单 : 1 值（1:1）
业务含义该货箱自身的箱号、承运商与转单号该运单关联的快递主单号、承运商转单号、商品数量合计
维护与引用运单管理原型箱级维护与展示财务「账单管理 → 账单详情」明细表按列引用
同名不同义提醒：transfer_no（运单级「转单号」）与原型箱级 transferNo（箱级「转单号」）不是同一个字段 —— 两者并存、语义不同，不得合并取值或以箱级值直接填充运单级。fba_no（FBA 单号）是运单级字段，与箱级字段无关。

字段名 (En)字段名 (Cn)类型 (Type)必填约束/索引枚举/备注

取值与实现约定:

  • fba_no / transfer_no：运单创建或下单回传时写入运单主表，箱级字段（sysNo / extNo / 承运商代码 / transferNo）继续按箱维护，两套数据并存
  • product_qty：采用「取数时实时汇总、不落库」方案 —— 财务账单明细查询时按运单汇总商品明细行数量，避免运单商品明细变更后数量快照失真

关联关系:
  • Many-to-One with Waybill（运单主表，本模块不建表；字段随运单实体落库）

四、关键设计说明

4.1 软删除策略

所有6张表均启用软删除（is_deleted 字段），业务数据不可物理删除。查询时自动过滤 is_deleted = false。

  • 级联规则：删除 vat_registration 时级联软删除其 vat_attachment 子表记录
  • 其他表无级联删除需求

4.2 乐观锁

所有6张表均启用乐观锁（version 字段）。核心并发场景：

  • VAT资料：员工审核时防止货主同时编辑（员工修改时也需乐观锁保护）
  • 标识/费用类型/物流事件/亚马逊事件：多运营同时编辑时的并发保护

4.3 JSON 字段使用场景

  • logistics_event.event_placeholders：事件占位符选择列表，选项有限且不需要独立查询，JSON数组存储
  • logistics_event.notify_placeholders：同上
  • 不使用JSON的场景：VAT附件（vat_attachment）拆为独立子表，因需单独管理文件的上传/下载/删除

4.4 纯逻辑实体说明

  • 货主用户：VAT资料表中的 user_id 引用外部用户模块，不建独立用户表
  • 运单 (Waybill)：通过查询接口获取VAT/费用类型/物流事件/标识数据，头程管理不持有运单数据
  • Ship Track系统：通过物流事件的 amazon_event_id 关联获取亚马逊事件代码，传递给Ship Track
