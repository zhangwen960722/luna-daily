- **流程**：生成（净额 < 0）→ **待发送**（可改账单日期 / 加删赔付流水 + 保存；可整张作废，流水释放回草稿池）→ 发送客户 → 客户确认（或发送满 7 个自然日系统自动确认，R16）→ 财务「**结转钱包**」→ 写一条 `flow_type = 70 赔付入账` 资金流水、客户可用额度增加 → 之后客户可核销其他账单或申请提现。

- **「结转钱包」= 终态、取消「撤销入账」**（产品口径"进了客户钱包就不能撤销"）：`flow_type = 80 赔付入账撤销` 不再存在 —— 钱包是客户可用额度容器，钱进去后可能已被拿去核销别的账单（那笔核销有效），逐笔回滚不可行也说不清；**纠错统一走对冲凭证**（运单侧新增正数流水 → 下期账单作为应收费抵扣）。落地：`财务_资金流水.html` 撤掉「撤销入账」按钮与整个 `reverseSettle`（操作列一并撤掉）、「赔付入账」类型 tag 加悬浮说明；员工端 / 货主端资金流水类型字典去掉「赔付入账撤销」；结转二次确认写明"结转不可撤销"。
- **补掉一处文档漏洞**：PRD §7.8「钱包余额变动（统一口径）」的公式原先**漏了赔付入账**（研发照它实现会少算这笔钱）→ 补 `赔付入账（贷记单结转）: balance_after = balance_before + |amount|` + 该流水的 7 条口径（来源唯一 / 关联单号与唯一约束 / 幂等事务 / 金额系统算 / 不可撤销 / 混同不配对 / 无手工入口）；§5.6 资金流水类型选项补「赔付入账」。
- **生成贷记单的弹窗文案改「三步走」**（产品反馈"客户确认后由财务结转钱包结清，这句没看懂"）：原文案一句话里主语跳三次、且"结清"容易被读反 → 改为 **先点明方向（我司应付客户）→ ①②③ 按顺序写（财务发送 → 客户确认赔付金额 → 财务结转钱包）→ 当场定义"结清 = 我司欠款兑付完毕，不是客户付款"→ 后续用途单独一句**；同步改弹窗内黄底提示、贷记单页顶部口径条、发送 / 结转二次确认、Toast。

### 2026-09-11 — 超级运价「附加费规则引擎」三态化重构 + 菜单定名「费用与标识规则」（原型 + 三份文档全部收口）

**核心：规则类型三态化（原「三选一」模型本身错了）**
- **根因**：「超重超长」的判定天然是「**维度 且 公式**」（如 `尾程=卡派 AND ((长+宽)*2+高>300 OR 长+宽*2+高*2>265)`），原「字段匹配 / 公式阈值 / 人工添加」三选一**强迫丢掉一边**
- **新三态**：`10 字段匹配`（维度 AND，≥1 条必填；计价单位 按票/按KG/按m³/按数量）／`40 字段&公式`（**新增**：维度仅「服务组合」多选、最多 1 行可为空 ＋ 公式 OR **≥1 条必填**；计价单位**仅按箱**）／`30 人工添加`（无触发条件；计价单位**仅按数量**）。原 `20:公式阈值` 废弃并入 40
- **动作类型两态**：加收费用 / 标识提醒。**「阻止下单」删除** → ⚠️ 拦截能力自此无载体，缺口登记为 TODO E7 待业务确认
- **附加费标识**：数组多选 → **单选且必选**（`tag_id` 单值），两种动作类型都要选

**菜单收敛 + 定名**
- 曾拆出「事件&规则」页（A 方案），终判**两页内容高度重叠**（同一套维度 + 公式）→ **删除该页与菜单项**，模型并入「字段&公式」
- 原「附加费规则」**更名为「费用与标识规则」**——旧名只能概括"加收钱"，而本菜单还承载「标识提醒」这类**只打标不收费**的动作。页面文件同步改名 `超级运价_费用与标识规则.html`，页面标题 / 列表卡片头 / 新增·编辑·查看弹窗标题 / 保存提示 / 状态变更提示五处同名；**实体名 `surcharge_rule` 与引擎名「附加费规则引擎」保持不变**

**其余落定**
- **触发节点改后台预置**（不对外配置、原型不展示，数据结构保留为 `node`）：字段匹配→运单收货完成／字段&公式→拣货（需拣货实测尺寸重量）／人工添加→人工触发；运单信息变更触发重扫，**业务审计后冻结、进账单后冻结、人工添加型永久豁免重扫**
