## ✅ 决策记录：超级运价 附加费 & 优惠体系（**最终态**）

> 本区是**已生效的最终决策**，供随时查证。原型与文档均已按此定稿。

### 菜单结构

| 决策 | 最终结论 |
|:---|:---|
| 菜单 | **只有一个菜单「费用与标识规则」**（2026-09-11 定名）。曾一度拆出「事件&规则」，但两页内容高度重叠（同一套维度 + 公式），**该菜单已删除**，公式类规则统一由「字段&公式」规则类型承载 |
| 曾用名 | 「附加费规则」（已更名）；实体名 `surcharge_rule` 与引擎名「附加费规则引擎」**保持不变** |

### 规则类型（三态）★ 核心

| 值 | 名称 | 触发条件 | 计价单位 |
|:--:|:---|:---|:---|
| 10 | **字段匹配** | 维度条件（AND，**≥1 条必填**） | 按票 / 按KG / 按m³（**无按数量**） |
| 40 | **字段&公式** | **维度条件（仅「服务组合」多选，最多 1 条，可为空）＋ 公式条件（OR，≥1 条必填）** | **仅按箱** |
| 30 | **人工添加** | 无（操作员在运单界面手动触发） | **仅按数量** |

> **原 `20:公式阈值` 已废弃**，能力并入 `40:字段&公式`。
> **根因**：「超重超长」的判定天然是「**维度 且 公式**」（如 `尾程=卡派 AND (长+宽)*2+高>300`），原「规则类型三选一」的模型强迫二选一 —— 要么丢维度、要么丢公式，**模型本身错了**。

### 触发节点（后台预置，原型不展示、数据结构保留为 `surcharge_rule.node`）

| 规则类型 | 触发节点 |
|:---|:---|
| 字段匹配 | **运单收货完成** |
| 字段&公式 | **拣货**（需要拣货实测尺寸/重量） |
| 人工添加 | **人工触发** |

- 通用：**运单信息变更 → 重新扫描费用规则**
- **重扫冻结边界**：收货完成前随意重扫 ／ 收货后~业务审计前可重扫并留痕 ／ **业务审计后冻结**（只能红冲或人工调整）／ **进账单后彻底冻结** ／ **人工添加型费用永远豁免重扫**
- **超重超长只在「拣货」触发**（下单不算）：下单尺寸是客户自填、算了也要被实测推翻
- ★ **查价阶段则「看录入方式」**（2026-09-12 定，原「运价查询阶段不计算」表述作废）：
  - **按单箱录入**（有长/宽/高）→ **能算**，超重超长按公式判定、体积重 = `长×宽×高 ÷ 计泡系数` → **作预估展示**
  - **按总体重量与体积录入**（无单箱尺寸）→ **算不出、不展示该项**
  - 预估**不落库、不进账单**；正式计费以**拣货实测**为准，结果区提示条保留

### 动作类型与标识

| 决策 | 结论 |

| `action_type` | **三值 → 两值**：10 加收费用 / 20 标识提醒。**`30:阻止下单` 已废弃**（一期不提供任何硬拦截能力） |
| 附加费标识 | **单选（`tag_id`）且必选**（不分动作类型）——标识提醒这个动作本身就是打标，不打标等于没作用 |

### 计价与优惠量纲 ★ 核心

| 决策 | 结论 |
|:---|:---|
| 计价单位位置 | **留在计价明细行内**（`pricing_rows[].pu`）——曾提为"规则级属性"，**已回退**：既然已定「只可选应收 + 固定 1 行」，单价本就唯一，提级是多余动作且造成层级错位 |
| 计价明细 | **费用方向固定「应收」**（`fee_direction` 恒 10）、**一期仅 1 行**、**同一费用方向最多 1 行**；应付方向二期拓展 |
| **优惠量纲** | **单价级**：优惠值作用于**计价明细「应收」行的单价**。校验 **`|优惠值| ≤ 应收单价`**、折扣率 `0.01 ≤ 率 ≤ 1`（一期不加价）、无应收行则拒绝配置优惠 |
| **计算与显示** | **`金额 + 优惠值`**（带符号）；负 → `-¥X`、正 → `+¥X`、0 → 「无优惠」（★ 见下方「优惠值正负号」） |
| `可优惠级别` | **永久删除**（字段 + 「可优惠性校验 BPR-4」能力一并取消）——它想表达的"最多能优多少"已由 `|优惠值| ≤ 应收单价` 精确表达 |
| 「不可优惠」政策落点 | 不靠字段约束，靠**"不给它建优惠规则"**；若业务需强控，二期在 `基础资料-费用类型` 加「是否可优惠」标记 |
| 优惠不得跨费用项抵扣 | **泡比优惠只作用于运费侧、不得抵扣附加费**；同源推广为「运费优惠只作用运费、附加费优惠只作用附加费」。最终报价必须**分段计算** |
| 判据完备性 | **逐条 `|优惠值| ≤ 应收单价` 只是配置期前置校验，不是「优惠后金额 ≥ 0」的充分条件**（折扣率 + 多条叠加仍可负，反例：`10 × 0.5 + (−10) = −5`）→ 「任一费用项最终金额不得为负」**必须独立实现** |

### 优惠对象与分期

| 决策 | 结论 |
|:---|:---|
| **客户特批进一期（三表统一）** | **三张优惠表（运费 / 泡比 / 附加费）口径统一**——`target_type` 一期同时开放 `10:客户特批` 与 `20:客户等级`。原「一期口径一致收缩为仅客户等级」作废 |
| 客户特批·前置校验 | `target_type=10` → `target_customers`（多选客户，取客商中心-客户管理启用客户）**必填**；`=20` → `target_levels`（多选等级）**必填**。二者是**两个独立命名空间** |
| 客户特批·优先级 | **客户特批 > 客户等级，高覆盖低、不叠加**，命中即覆盖等级规则 —— **一期即生效**。（⚠️ 「特批劣于等级」的例外见待确认 **T1**） |
| **审批编号进一期** | `approval_no`（字符串30）：**客户特批时必填**、客户等级时留空。**UI 有「审批编号」列**（仅当存在客户特批行时出现）。★ 一期边界：**人工录入编号，不对接飞书审批流**（无审批单同步 / 无「审批中·已通过」状态机）；审批流自动对接留二期 |
| **泡比优惠进一期** | 由 Phase 2（模块 M，4 项）**整体改为 Phase 1**。**Phase 1 功能数 55 → 59**，模块 M 优先级 **P2 → P0**。一期口径：密度阈值阶梯 + 固定减免 + 客户等级/客户特批 + 永久·固定期限 + 费用方向固定应收 + 审批编号（特批时）。匹配：泡比 = 实重(kg) ÷ 体积(m³)，≥ 阈值即命中；**多条命中取阈值最大那一档（不叠加）**；**与运费优惠叠加** |
| **优惠唯一性精确口径** | **同一父实体 × 同一对象类型 × 同一目标，最多一条「生效中」的规则**。① **只看生效中**（已失效的历史规则不占名额）；② **命名空间按对象类型分离**（特批比客户ID、等级比等级ID）；③ **泡比优惠另加「密度阈值」维度**（同一目标在不同阈值档可各配一条 = 阶梯）。**作用域 = 同一父实体（组合/附加费规则）内**，不做全系统唯一 |
| **仍留 Phase 2** | ① `单次有效`；② 运费/泡比一期**仍只有固定减免**（附加费一期两种都有）；③ 浮动优惠（券/满减/限时活动）；④ 营销模块独立立项；⑤ 叠加顺序可配；⑥ **飞书审批流自动对接** |

### 优惠值正负号（★ 2026-09-12 定，产品与开发共同确认）

| | 约定 |
|:---|:---|
| **固定减免** | **负数 = 减钱（正向优惠）** ｜ **正数 = 加价（反向优惠）** |
| **计算** | **`金额 + 优惠值`** |
| **显示** | 负 → `-¥X`；正 → `+¥X`；0 → 「无优惠」 |
| **上限校验** | **`|优惠值| ≤ 应收单价`**（绝对值） |
| **折扣率** | **不变**（乘数：`<1` 折扣 / `=1` 原价 / `>1` 加价；一期 `0.01~1` 不支持加价） |
| **报价公式** | `最终报价 = (公布价 + 运费优惠值 + 泡比优惠值) + (附加费合计 + 附加费优惠值合计)` |

### 公式（「字段&公式」型）

| 决策 | 结论 |
|:---|:---|
| 归属 | 只在「字段&公式」类型下；**公式条件必填**（≥1 条，逐条查空） |
| 可用变量 | **长、宽、高、重量、材积重** |
| **`材积重` 取数**（2026-09-12 定） | 「材积重」是**体积重的统称**——**货箱上的「材重」与「重量方数」都属于材积重**，按计费方式取其一：按 **KG** → 货箱**材重**（`长×宽×高 ÷ 计泡系数`，原型系数 **6000**）；按 **m³** → 货箱**重量方数**（`实重 ÷ 计方系数`，原型系数 **363**）。公式中直接引用该值即可。**原型上不解释取数来源**（只保留变量名），口径写在产品文档里 |
| 运算符 | 算术 `+ - * / ( )`；比较 `> < >= <= =` |
| 维度限制 | 「字段&公式」的维度**只能选「服务组合」**（多选），且**最多 1 行** |
